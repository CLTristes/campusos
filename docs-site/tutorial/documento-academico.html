Importar o documento acadêmico

O aluno já está autenticado (token do tutorial anterior). Ele sobe o histórico escolar, uma IA lê em segundo plano, ele confere o que foi lido e confirma — só então a graduação inteira aparece no sistema.

Três passos, e só o último escreve dado. Sobe → a IA lê (assíncrono) → o aluno confere e confirma. Um erro de leitura vira uma correção de 30 segundos na tela de conferência, nunca um histórico corrompido.
1Enviar o documento

O histórico escolar reconstitui a graduação inteira num upload só — é o caminho recomendado. PDF ou foto, até 20 MB.

POST /api/v1/me/academic-documents · multipart/form-data
kind: "transcript"
file: <arquivo — pdf, png ou jpg, até 20MB>

// 202 Accepted — a leitura roda em fila, não trave a tela esperando
{
  "data": {
    "id": "01a0b8...",
    "kind": "transcript",
    "status": "uploaded",
    "status_label": "Recebido",
    "is_pending": true,
    "confidence": null,
    "provider": null,
    "failure_reason": null,
    "extraction": null,
    "parsed_at": null,
    "confirmed_at": null
  }
}

Guarde o id — é ele que os dois próximos passos usam. Limite de 10 envios por minuto por conta.

2Consultar o status (polling)

Enquanto is_pending for true, continue consultando — a cada 2-3 segundos é razoável. O ciclo do documento:

  • uploaded
  • →
  • processing
  • →
  • parsed
  • →
  • confirmed

Com failed como desvio possível a qualquer momento (estado final, sem retry). Faça polling em:

GET /api/v1/me/academic-documents/{id}
// enquanto lê:
{ "data": { "id": "01a0b8...", "status": "processing", "is_pending": true, "..." : "..." } }

// leitura concluída — "extraction" é o que a tela de conferência mostra
{
  "data": {
    "id": "01a0b8...",
    "status": "parsed",
    "status_label": "Aguardando sua conferência",
    "is_pending": false,
    "confidence": 1.0,
    "provider": "gemini:gemini-3.6-flash",
    "failure_reason": null,
    "extraction": {
      "kind": "transcript",
      "meta": {
        "student_name": "Felipe Kurt Pohling", "registration_number": "2567857",
        "course": "Sist. Informação", "course_code": "25", "curriculum_code": "45",
        "campus": "Francisco Beltrão", "entry_term": "1/2023", "current_period": 8, "status": "Regular"
      },
      "lines": [
        { "code": "ARC102", "name": "Arquitetura De Computadores", "year": 2023, "period": 1,
          "class_code": "1SI", "status": "Aprovado Por Nota/Frequência", "grade": 8.5, "attendance": 91.2, "hours": 60 }
      ],
      "confidence": 1.0, "provider": "gemini:gemini-3.6-flash"
    },
    "parsed_at": "2026-09-19T02:16:00+00:00",
    "confirmed_at": null
  }
}

// leitura falhou (documento ilegível, não é um histórico) — estado final
{ "data": { "id": "01a0b8...", "status": "failed", "status_label": "Não foi possível ler",
  "is_pending": false, "failure_reason": "O arquivo não parece um documento acadêmico." } }

Renderize a tela de conferência a partir de extraction.lines — uma linha editável por disciplina, com code, status (o texto exato do documento — deixe editável, é o que o passo 3 espera de volta), grade, attendance e year/period. attendance: null significa "não se aplica" (exame de suficiência, estágio) — não é um zero, não mostre como zero.

3Confirmar — só aqui nasce a matrícula

O aluno revisou (e pode ter corrigido) as linhas na tela de conferência. Mande de volta exatamente o que ele confirmou — não a extração crua.

POST /api/v1/me/academic-documents/{id}/confirm
// request — registration_id é OPCIONAL: sem vínculo ainda, o próprio
// confirm cria um a partir do cabeçalho que a IA leu (curso, RA, ingresso)
{
  "lines": [
    { "code": "ARC102", "year": 2023, "period": 1,
      "status": "Aprovado Por Nota/Frequência", "grade": 8.5, "attendance": 91.2 }
  ]
}

// 200 — a matrícula nasceu, a barra de progresso já pode ser consultada
{
  "data": { "id": "01a0b8...", "status": "confirmed", "confirmed_at": "2026-09-19T02:17:00+00:00", "..." : "..." },
  "imported": 50,
  "pending": [
    { "code": "FSI103", "reason": "Disciplina não está no catálogo do curso." }
  ]
}

pending[] lista linhas que não bateram com o catálogo (disciplina extinta, mudança de matriz antiga) — mostre como aviso, nunca como erro: as outras 50 linhas do exemplo acima já viraram matrícula normalmente. Depois do 200, redirecione pra tela de progressão (tutorial 03).

422 — erros possíveis
// documento já confirmado antes
{ "errors": { "request_id": ["Este documento já foi confirmado."] } }

// sem registration_id E sem curso/ingresso reconhecíveis no cabeçalho lido
{ "errors": { "registration_id": ["Não foi possível identificar o vínculo automaticamente a partir do documento. Informe registration_id."] } }
A IA nunca escreve matrícula. Ela só preenche extraction; a tela de conferência é o único lugar onde o aluno vê o que foi lido antes de existir de verdade no sistema. É isso que transforma um erro de leitura numa correção de 30 segundos em vez de um histórico corrompido.
Erro de rede ao subir o arquivo é diferente de "documento ilegível". Se o polling do passo 2 voltar pra uploaded depois de já ter ido pra processing, é sinal de instabilidade transitória — o back-end está reprocessando sozinho, não precisa reenviar o arquivo. Só trate como definitivo o status failed.
