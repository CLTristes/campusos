A barra de progresso e o catálogo

Um endpoint sozinho desenha a tela principal do produto: quanto falta pra formar, o que está pendente por período, e a previsão de formatura pelo ritmo real do aluno — não pelo ideal da matriz.

1A progressão do aluno autenticado

Chame assim que o aluno já tiver um vínculo (depois do tutorial 02, ou de um vínculo trazido por seeder/coordenação):

overall.percentage é a barra principal da tela. extension.counts_in_total: false é proposital — a carga extensionista (240h) já está embutida dentro das disciplinas contadas em overall; somá-la de novo inventaria horas que o aluno não precisa cursar. Mostre-a como um indicador à parte, nunca somado à barra principal.

2O que falta, por período

pending_subjects[] já vem ordenado pelo período sugerido da matriz — agrupe por term na tela ("o que falta no 8º período", "no 7º período"...). in_progress: true marca o que o aluno já está cursando agora — não é "faltando" no sentido de urgente, é "em andamento".

3Previsão de formatura

forecast calcula pelo ritmo real do aluno (horas aprovadas ÷ semestres cursados), não pelo ritmo ideal da matriz — é o número que a pessoa precisa ouvir, não o que soa bonito. Mostre remaining_terms como "você se forma em ~N semestres, no ritmo atual". at_risk: true significa que o ritmo real não cabe no prazo que resta até o limite de integralização (terms_until_deadline) — é o gatilho certo pra um alerta visual, não pra esconder o número.

4O catálogo — curso e matriz

Para telas de "o que é o curso" ou "grade completa" (não depende de vínculo, é dado público da instituição):

GET /api/v1/courses
{ "data": [
  { "id": "01a0b8...", "code": "25", "name": "Bacharelado em Sistemas de Informação",
    "degree": "bachelor", "degree_label": "Bacharelado", "shift": "evening", "shift_label": "Noturno",
    "campus": { "id": "01a0b8...", "code": "FB", "name": "Francisco Beltrão" } }
] }
GET /api/v1/courses/{course}/curriculum
{ "data": {
  "id": "01a0b8...", "code": "45", "name": "Sistemas De Informação 02", "version": 1, "status": "active",
  "workload": { "mandatory_hours": 2730, "elective_hours": 210, "standalone_extension_hours": 60,
    "total_hours": 3000, "extension_hours": 300, "extension_counts_in_total": false },
  "rules": { "expected_terms": 8, "max_terms": null, "max_term_hours": 390, "max_weekly_deficit": 16 },
  "elective_groups": [
    { "code": "941", "name": "Optativas", "required_hours": 210, "weekly_hours": 14,
      "first_term": 5, "last_term": 8, "weekly_hours_per_term": 3.5 }
  ],
  "terms": [
    { "term": 1, "subjects": [
      { "code": "ARC102", "name": "Arquitetura De Computadores", "nature": "mandatory",
        "model": "basic_scientific", "weekly_hours": 4, "hours": 60, "extension_hours": 0,
        "elective_group": null, "prerequisites": [] }
    ] }
  ]
} }

terms[] já vem agrupado por período — é a "grade curricular" pronta pra desenhar em colunas. prerequisites[] de cada disciplina traz o que ela exige (por disciplina, por período mínimo, ou por carga horária mínima); disciplina sem nada aí não tem pré-requisito.

O sistema não recalcula a situação de uma matrícula importada. Se o histórico diz "aprovado", o sistema mostra "aprovado" — mesmo que a regra de aprovação da UTFPR (frequência × nota) desse outro resultado calculando do zero. Não construa uma tela que "corrija" isso; é uma decisão de produto deliberada, não uma lacuna.
