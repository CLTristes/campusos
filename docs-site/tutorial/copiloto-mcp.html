Copiloto MCP

Não existe uma "tela do copiloto" — existe uma tela de configurações que gera um token, e um cliente MCP externo (Claude Desktop e afins) que passa a responder com o contexto real da graduação do aluno. Este tutorial cobre as duas pontas: o que o seu front precisa expor, e o que o cliente MCP enxerga do outro lado.

Não existe tela pra isto ainda no protótipo — quem for demonstrar chama POST /auth/mcp-token na mão (Postman/curl) e cola o token no cliente MCP. Este tutorial é o roteiro de como a tela DEVERIA funcionar quando alguém da dupla construir.
1Gerar o token do copiloto

É um token SEPARADO do token de login — nunca reaproveite o token da sessão do app pra conectar um cliente MCP externo. Chamar de novo troca o token: o anterior para de funcionar na hora.

POST /api/v1/auth/mcp-token
{ "allow_write": false }   // omitir tem o mesmo efeito

// 200 — só leitura (padrão)
{ "token": "12|AbCdEf...", "abilities": ["mcp:read"] }

// 200 — com allow_write: true
{ "token": "13|GhIjKl...", "abilities": ["mcp:read", "mcp:write"] }

Mostre o token UMA vez, com um botão "copiar" — como qualquer token de API, ele não pode ser recuperado depois, só substituído por um novo (que invalida este). Deixe allow_write como um toggle explícito, desligado por padrão: só liga quem realmente quer que a IA crie anotações em seu nome.

2Conectar o cliente MCP

O endpoint do servidor é POST /mcp — configurável em qualquer cliente MCP que aceite um servidor remoto autenticado por Bearer token. A tela só precisa mostrar a URL completa e o token gerado no passo 1, prontos pra colar na configuração do cliente.

Configuração do cliente MCP
{
  "campusos": {
    "url": "https://SEU-DOMINIO/mcp",
    "headers": { "Authorization": "Bearer 12|AbCdEf..." }
  }
}

Sem o header Authorization válido, POST /mcp recusa ANTES de qualquer tool rodar — o cliente MCP mostra isso como "servidor indisponível/não autenticado", não como um erro de uma tool específica.

3As sete tools — o que a IA pode fazer

Não há endpoint HTTP pra "listar tools" — é o próprio protocolo MCP que expõe isso ao cliente. Esta tabela é a referência que o front (ou a documentação de onboarding) usa pra explicar ao aluno o que o copiloto sabe fazer:

ToolRespondeEscreve?
minha_progressaoQuanto falta, por faixa de hora, com previsão de formaturanão
disciplinas_liberadasO que dá pra pegar no próximo semestre, e o que trava cada umanão
acervo_da_disciplinaAs anotações públicas que o aluno tem direito de ver naquela disciplinanão
buscar_anotacoesBusca por palavra-chave em todo o acervo a que ele tem acessonão
minha_agendaTarefas próprias e da turma, por prazonão
minhas_horasComplementares por categoria, com teto e o que foi perdidonão
criar_anotacaoCria uma anotação pessoal (nasce sempre privada)sim, a única

Todas as seis de leitura respondem com o MESMO formato que o endpoint REST equivalente já devolve — não é um resumo em texto livre, é o dado estruturado, e é o cliente MCP (a IA) quem decide como apresentar em português na conversa.

4criar_anotacao — a única que escreve
criar_anotacao (chamada pelo cliente MCP, não HTTP direto)
{
  "title": "Critérios de convergência — resumo",
  "body_md": "1. Teste da razão... 2. Teste da raiz...",
  "kind": "summary",
  "subject_id": "01a0b8..."   // opcional
}

// sucesso — mesmo shape do POST /notes REST
{ "data": { "id": "01a0b8...", "title": "Critérios de convergência — resumo",
  "kind": "summary", "visibility": "private", "author": {...} } }

// erro — token sem a ability mcp:write
{ "error": "Este token do copiloto não tem permissão de escrita. Gere um
  novo token com escrita habilitada em Configurações." }

A anotação criada pelo copiloto nasce sempre privada — exatamente como uma criada pelo app. Publicá-la pro acervo (subir a escada de visibilidade) continua sendo um passo separado e deliberado, feito no app, nunca pela IA.

Duas checagens de permissão, não uma. POST /mcp já exige mcp:read na borda — sem isso, nenhuma das sete tools roda. criar_anotacao checa mcp:write DENTRO de si mesma, além disso. Um token só-leitura tentando criar uma anotação recebe o erro do passo 4 nesta MESMA chamada — não é um 403 de rota, é a tool recusando o próprio pedido.
Nenhuma tool toca matrícula, nota do histórico ou horas. A IA nunca grava vínculo, aprovação ou hora complementar — só lê o que essas regras já calcularam, ou cria uma anotação pessoal. Se um dia uma tool nova parecer precisar de um if de regra de negócio pra funcionar, é sinal de que a regra não existe na Action certa — não se resolve isso dentro da tool.
