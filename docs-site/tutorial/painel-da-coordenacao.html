Painel da coordenação

Quatro telas pra quem coordena, não pra quem estuda: onde a turma empaca, quanto isso custa em semestres, quem está perto do limite, e o que vem represado pro próximo período. As quatro respostas são sempre agregadas — nenhuma delas devolve o nome de um aluno.

Estas quatro rotas exigem papel de coordenação. Um aluno autenticado recebe 403 nas quatro — a tela de coordenação nem deve tentar renderizar o painel pra quem não passou pelo RBAC de borda (role:coordinator,institution_admin).
1Onde a turma empaca

Taxa de reprovação por disciplina, nos últimos last_terms termos com matrícula — nota e falta separadas, porque conteúdo difícil e problema de permanência pedem intervenções diferentes.

GET /api/v1/staff/insights/bottlenecks?last_terms=4
{ "data": [
    { "subject_code": "MAT029", "subject_name": "Cálculo 2",
      "total_attempts": 40, "failed_grade": 15, "failed_absence": 6,
      "failed_both": 0, "failure_rate": 0.525 }
  ] }

failure_rate já vem calculado (aprovados/exame contam como sucesso, o resto como tentativa reprovada) — use pra ordenar a lista de gargalo do mais crítico pro menos crítico, sem recalcular nada no front.

2Quanto custa — atraso por coorte
GET /api/v1/staff/insights/cohorts
{ "data": [
    { "entry_term": "2022/1", "active_registrations": 38, "avg_delay_terms": 2.4 }
  ] }

avg_delay_terms é a média, entre os vínculos ATIVOS daquela coorte de ingresso, de quantos termos além do previsto pela matriz o aluno já está cursando. Não inclui formados nem desistentes — é "atraso até agora", não "atraso até a formatura".

3Quem está perto do limite
GET /api/v1/staff/insights/at-risk?within=2
{ "data": { "count": 12, "within_terms": 2 } }

Um número só: quantos vínculos ativos têm previsão de formatura (o mesmo forecast.terms_until_deadline de GET /me/progress, reaproveitado — nunca recalculado do zero) dentro de within termos. É o aviso de jubilamento que a instituição raramente dá a tempo, virado KPI.

4O que está represado
GET /api/v1/staff/insights/demand
{ "data": [
    { "subject_code": "ES52C", "subject_name": "Engenharia de Software II", "demand": 22 }
  ] }

Quantos vínculos ativos já estão elegíveis (mesma regra de GET /me/next-term) para cada disciplina que ainda não cursaram — planejamento de oferta direto, em vez do chute de sempre sobre quantas turmas abrir.

Piso de anonimato: menos de 5 não aparece. Uma disciplina/coorte com menos de 5 tentativas/vínculos/elegíveis simplesmente não entra em nenhum dos quatro data[] — não vem com um valor censurado, o item some. Se a tela espera uma lista fixa de disciplinas e uma delas não aparecer, é o piso agindo, não um bug: mostre "dado insuficiente para exibir" só se for útil ao coordenador saber que a turma é pequena demais pra métrica, nunca tente reconstituir o número escondendo menos.
O escopo nunca vem do front. Um coordinator só enxerga o próprio curso (users.course_crs_id, resolvido no servidor); um institution_admin enxerga a instituição inteira. Não existe parâmetro course_id em nenhuma das quatro rotas — não tem como pedir "me mostra o curso do outro coordenador" mesmo manipulando a query string.
Coordenador sem curso configurado — se users.course_crs_id estiver vazio pra um usuário coordinator, as quatro rotas devolvem 422 com a mensagem "Coordenador sem curso configurado — fale com a gestão da instituição." em vez de silenciosamente mostrar zero em tudo. Trate esse caso na tela como um estado de configuração pendente, não como "sem dados".
