Horas complementares e certificados

O aluno declara uma atividade com certificado e vê na hora quanto dela conta, respeitando o teto da categoria — o contador é paralelo à barra de progresso, nunca uma segunda fonte de verdade para o total de horas.

Isto NUNCA muda o número de GET /me/progress. É um tracker paralelo — o teto por categoria é informação que o aluno precisa pra não desperdiçar horas declarando de mais numa categoria já estourada, não uma segunda barra de progresso.
1O teto de cada categoria

Vem embutido na matriz — sem endpoint próprio, é a mesma chamada que já monta a grade curricular:

GET /api/v1/courses/{course}/curriculum
{ "data": {
  "..." : "...",
  "complementary_categories": [
    { "id": "01a0b8...", "name": "Participação em eventos", "max_hours": 40,
      "conversion_note": "até 10h por evento; exige certificado" },
    { "id": "01a0b8...", "name": "Monitoria", "max_hours": 80, "conversion_note": null }
  ]
} }

Use complementary_categories pra montar o seletor de categoria da tela de declaração — mostre o teto de cada uma ali, antes do aluno digitar quantas horas.

2Declarar — com o aviso já na resposta
POST /api/v1/me/complementary-activities · multipart/form-data
category_id: "01a0b8..."
title: "Semana Acadêmica de Sistemas de Informação"
hours_claimed: 20
issued_at: "2026-05-15"
certificate: <arquivo — pdf, png ou jpg, até 10MB, opcional>

// 201 — dentro do teto
{ "data": { "id": "01a0b8...", "title": "Semana Acadêmica...", "hours_claimed": 20,
  "hours_granted": null, "status": "submitted", "has_certificate": true,
  "category": { "id": "01a0b8...", "name": "Participação em eventos", "max_hours": 40 } },
  "capped": false, "hours_not_counted": 0 }

// 201 — estourou o teto (66h já declaradas antes + 20h agora, teto 40h)
{ "data": { "..." : "..." }, "capped": true, "hours_not_counted": 46 }

// 422 — categoria de outra matriz
{ "errors": { "category_id": ["Esta categoria não pertence à sua matriz."] } }

capped/hours_not_counted já vêm calculados nesta MESMA resposta — o front não precisa de uma segunda chamada pra saber se estourou. Mostre o aviso preventivo assim que o 201 voltar, não espere o aluno ir procurar.

hours_granted na declaração individual fica sempre null — o corte é calculado agregado POR CATEGORIA (próximo passo), nunca gravado por certificado.

3Minhas atividades e o resumo por categoria
GET /api/v1/me/complementary-activities
{
  "data": [
    { "id": "01a0b8...", "title": "Semana Acadêmica...", "hours_claimed": 20, "status": "submitted",
      "has_certificate": true, "category": { "name": "Participação em eventos", "max_hours": 40 } }
  ],
  "summary": [
    { "category": { "id": "01a0b8...", "name": "Participação em eventos", "max_hours": 40 },
      "hours_claimed": 86, "hours_granted": 40, "hours_not_counted": 46, "capped": true }
  ]
}
86h declaradas · teto 40h46h perdidas

Use summary pra desenhar uma barra por categoria (a proporção contada × o teto, como acima) — é a tela que resolve a frustração clássica ("eu tinha 60 horas de evento e só contaram 40") virando informação do primeiro dia, não surpresa do último.

Sem fila de homologação ainda. status nasce sempre submitted e já conta — draft também contaria se existisse, só rejected não conta. Mostre a ressalva "valores declarados, sujeitos a homologação futura" na tela em vez de prometer um "aprovado pela coordenação" que ainda não existe.
