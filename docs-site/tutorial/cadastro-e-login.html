Cadastro e login

Sem tela de "escolha sua universidade": a instituição é resolvida pelo domínio do e-mail. O aluno sai logado do próprio cadastro — a verificação por código roda em paralelo, sem travar nada.

Não existe seletor de universidade. O back-end resolve a instituição a partir do que vem depois do @ no e-mail (entities.ent_email_domain) — o aluno da UTFPR só precisa digitar seu.nome@alunos.utfpr.edu.br. Se o domínio não estiver habilitado, o cadastro é recusado com 422; não invente uma tela de "instituição não encontrada" separada, a mensagem de erro já serve.
1O formulário de cadastro

Cinco campos, nenhum seletor de instituição:

  • nametexto livre, obrigatório
  • emailobrigatório — o domínio decide a instituição
  • passwordmínimo 8 caracteres, obrigatório
  • password_confirmationobrigatório, precisa bater com password
  • deviceopcional — rótulo do token, pra poder revogar só este dispositivo depois
POST /api/v1/auth/signup
// request
{
  "name": "Felipe Kurt Pohling",
  "email": "felipe@alunos.utfpr.edu.br",
  "password": "senha-forte-123",
  "password_confirmation": "senha-forte-123"
}

// 201 Created — o aluno já está autenticado
{
  "data": {
    "id": "01a0b8...",
    "name": "Felipe Kurt Pohling",
    "email": "felipe@alunos.utfpr.edu.br",
    "role": "student",
    "role_label": "Estudante",
    "registration_number": null,
    "email_verified": false,
    "entity_id": "01a0b8...",
    "campus": null,
    "enabled_modules": []
  },
  "token": "1|k3j2h4g5f6d7s8a9"
}

Guarde o token (localStorage/secure storage) e navegue direto pra tela principal do produto — não existe passo de login separado depois do cadastro. registration_number vem null porque o RA só aparece depois que o aluno importar o histórico escolar (tutorial 02).

422 — erros possíveis
// domínio de e-mail não habilitado para cadastro livre
{ "message": "Use seu e-mail institucional — este domínio não está habilitado para cadastro.",
  "errors": { "email": ["Use seu e-mail institucional — este domínio não está habilitado para cadastro."] } }

// e-mail já cadastrado nesta instituição
{ "message": "Já existe uma conta com este e-mail nesta instituição.",
  "errors": { "email": ["Já existe uma conta com este e-mail nesta instituição."] } }

// senhas não coincidem
{ "errors": { "password": ["A confirmação de senha não bate."] } }
2Confirmar o e-mail (opcional, em paralelo)

Um e-mail com um código de 6 dígitos chega logo depois do cadastro. Isto não bloqueia nada — o aluno já está usando o sistema desde o passo 1. Mostre um aviso discreto ("confirme seu e-mail") em vez de uma tela cheia; o aluno pode ignorar por dias sem perder acesso.

POST /api/v1/auth/verify-email
// request (autenticado)
{ "code": "482913" }

// 200 — sucesso
{ "data": { "id": "01a0b8...", "email_verified": true, "..." : "..." } }

// 422 — código errado, expirado (15 minutos) ou já verificado
{ "errors": { "code": ["Código inválido."] } }

Código expirado? Reenvie um novo — mesmo padrão de rate limit de um "reenviar SMS", só que por e-mail:

POST /api/v1/auth/verify-email/resend
// sem corpo, autenticado — 204 No Content
// limite: 3 tentativas a cada 10 minutos
3Login (quem já tem conta)

Para quem já se cadastrou antes, ou entrou por outro caminho (coordenação, seeder de dev):

POST /api/v1/auth/login
// request
{ "email": "aluno@alunos.utfpr.edu.br", "password": "campusos" }

// 200 — mesmo formato de resposta do signup
{ "data": { "id": "01a0b8...", "email": "aluno@alunos.utfpr.edu.br", "role": "student", "..." : "..." }, "token": "1|abc..." }

// 422 — e-mail OU senha errados dão A MESMA mensagem (nunca revele qual dos dois falhou)
{ "message": "Credenciais inválidas.", "errors": { "email": ["Credenciais inválidas."] } }

Um caso raro que vale tratar: se o mesmo e-mail existir em mais de uma instituição, o login responde 422 pedindo entity_id — mostre uma lista simples com o nome de cada instituição encontrada (a API não devolve essa lista pronta; se isso acontecer na prática, é sinal de pedir mais contexto ao back-end antes de desenhar a tela).

4Quem sou eu / sair

No boot da aplicação (refresh de página, abrir o app), confirme o token com:

GET /api/v1/auth/me
// autenticado — mesmo formato de UserResource dos passos anteriores
// 401 se o token não existir mais (foi revogado, expirou) — mande pra tela de login
POST /api/v1/auth/logout
// autenticado, sem corpo — 204 No Content
// revoga SÓ o token deste dispositivo; outras sessões continuam logadas
Toda mensagem de erro da API já vem pronta pra exibir — o message no topo do 422 traz a primeira, errors.<campo>[] traz todas. Use a chave (email, password, code) pra saber em qual input pintar o erro; o texto já está em português, não precisa de dicionário de mensagens no front.
