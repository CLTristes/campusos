Pré-requisitos e simulação de reprovação

Duas perguntas que o desafio 5.1 pede e nenhum sistema acadêmico responde direito: o que eu posso pegar agora, e o que aconteceria se eu reprovasse nesta disciplina? As duas são puro cálculo sobre o histórico e a matriz que já existem — nenhuma tabela nova.

1O que libera e o que trava
GET /api/v1/me/next-term
// 200
{ "data": {
  "current_period": 6,
  "eligible": [
    { "code": "ES52C", "name": "Engenharia de Software II" }
  ],
  "blocked": [
    { "code": "ES62A", "name": "Compiladores", "blocked_by": [
      { "type": "subject", "subject": { "code": "LIP301", "name": "Linguagens Formais" },
        "reason": "Precisa ter aprovado Linguagens Formais." }
    ] },
    { "code": "EST501", "name": "Estágio Curricular Obrigatório", "blocked_by": [
      { "type": "minimum_term", "subject": null,
        "reason": "Exige estar a partir do 5º período (você está no 6º)." }
    ] }
  ]
} }

Cada travada vem com blocked_by[] explícito — nunca mostre só a etiqueta "travada". O tipo subject aponta a disciplina exigida; minimum_term/minimum_hours não têm disciplina nenhuma (subject: null) — o motivo já vem em texto pronto pra tela.

Disciplina aprovada ou em curso agora não aparece nem em eligible nem em blocked — a lista é só o que ainda não foi começado.

2E se eu reprovar?

Sem escrita nenhuma no banco — é seguro chamar quantas vezes o aluno quiser mudar a hipótese:

POST /api/v1/me/simulate
{ "fail": ["LIP201"] }

// 200 — o exemplo real da matriz: reprovar Linguagem de Programação
// atrasa toda a cadeia que depende dela, um período por vez
{ "data": {
  "failed": ["LIP201"],
  "current_period": 3,
  "affected_subjects": [
    { "subject": { "code": "POO303", "name": "Programação Orientada a Objetos" },
      "real_earliest_period": 3, "simulated_earliest_period": 4, "delay_terms": 1 },
    { "subject": { "code": "WBE501", "name": "Desenvolvimento Web Back-End" },
      "real_earliest_period": 4, "simulated_earliest_period": 5, "delay_terms": 1 }
  ],
  "estimated_graduation_delay_terms": 1
} }

// 422 — código que não existe na matriz
{ "errors": { "fail.0": ["..."] } }
  • LIP201 reprovada
  • →
  • POO303 +1 período
  • →
  • WBE501 +1 período

affected_subjects só lista quem de fato mudou — a disciplina reprovada (LIP201) nunca aparece na própria lista, ela é a entrada da simulação, não um efeito colateral. Ordene pela tela por delay_terms desc — o maior impacto primeiro é o que gera o "uau" no pitch.

"Período atual" é uma aproximação. É o número de semestres reais que o aluno já cursou (current_period), não o déficit de carga horária semanal acumulado que o histórico oficial calcula. Bate certo pra quem nunca trancou nem teve lacuna entre semestres — não prometa precisão absoluta pra todo mundo na tela.
estimated_graduation_delay_terms é o maior atraso entre as disciplinas afetadas — não inclui disciplinas que já tinham seu próprio motivo de atraso (um minimum_term fixo, por exemplo), que permaneceriam com o mesmo período em qualquer cenário e não deveriam contar como "efeito da reprovação simulada".
