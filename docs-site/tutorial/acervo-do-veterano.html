O acervo do veterano

O caderno pessoal do aluno (5.1) e o acervo compartilhado entre semestres (5.2) são o MESMO endpoint — o que muda é só o campo visibility. Uma nota nasce sempre privada; publicar é um passo separado e deliberado.

A escada de cinco degraus. Toda nota nasce private. Publicar sobe um degrau; despublicar (voltar pra private) sempre funciona, sem pré-condição nenhuma.
  • privatepadrão — só o autor enxerga
  • offeringa turma, naquele semestre específico
  • subjectqualquer pessoa que já cursou a disciplina, em qualquer semestre — é aqui que o acervo do veterano acontece
  • coursetodo o curso
  • institutiona instituição inteira
1Criar uma nota

Nasce sempre privada — mesmo que você mande outra visibilidade no request, ela é ignorada.

POST /api/v1/notes
// request
{
  "title": "Resumo da P2 — Séries e integrais impróprias",
  "body_md": "## O que cai\n\nA prova cobra séries e quase nada de integrais impróprias...",
  "kind": "summary",
  "subject_id": "01a0b8..."
}

// 201 Created — sempre "private", não importa o que foi mandado
{
  "data": {
    "id": "01a0b8...",
    "title": "Resumo da P2 — Séries e integrais impróprias",
    "body_md": "## O que cai...",
    "kind": "summary", "kind_label": "Resumo",
    "visibility": "private", "visibility_label": "Privada",
    "author": { "id": "01a0b8...", "name": "Um Veterano" },
    "subject_id": "01a0b8...", "offering_id": null, "course_id": null,
    "term": null,
    "published_at": null,
    "created_at": "2026-09-19T10:00:00+00:00"
  }
}

kind: summary (resumo) · past_exam (prova antiga) · solved_exercise_list (lista resolvida) · material · tip (dica). São filtráveis — deixe o aluno escolher o tipo antes de escrever, não depois.

2Publicar — subir na escada

Um botão "compartilhar" separado do botão "salvar" — publicar é sempre um ato deliberado.

POST /api/v1/notes/{note}/visibility
// request — publicar pra quem já cursou a disciplina, em qualquer semestre
{ "visibility": "subject", "subject_id": "01a0b8..." }

// 200 — "published_at" foi preenchido nesta chamada
{ "data": { "id": "01a0b8...", "visibility": "subject", "visibility_label": "Quem já cursou esta disciplina",
  "published_at": "2026-09-19T10:05:00+00:00", "..." : "..." } }

// 422 — publicar pra "subject"/"offering" sem a disciplina/turma informada
{ "errors": { "subject_id": ["Informe a disciplina antes de publicar para quem já a cursou."] } }

// 403 — só o autor muda a visibilidade da própria nota
{ "message": "Esta nota não é sua." }

Despublicar é a mesma chamada, sem pré-condição nenhuma:

POST /api/v1/notes/{note}/visibility
{ "visibility": "private" }
// 200 — sai do acervo na hora. published_at NÃO é apagado (é o histórico
// de quando a nota entrou no acervo pela primeira vez)
3Ver o acervo de uma disciplina

A mesma listagem serve pro caderno pessoal (sem filtro) e pro acervo de uma disciplina específica (com subject_id). O que volta já é exatamente o que o usuário autenticado tem direito de ver — sem lógica de permissão nenhuma no front.

GET /api/v1/notes?subject_id={id}
// 200 — ordenado por data de publicação (mais recente primeiro)
{ "data": [
  {
    "id": "01a0b8...", "title": "Resumo da P2 — Séries e integrais impróprias",
    "kind": "summary", "kind_label": "Resumo",
    "visibility": "subject", "visibility_label": "Quem já cursou esta disciplina",
    "author": { "id": "01a0b8...", "name": "Um Veterano" },
    "term": { "year": 2024, "period": 1 },
    "published_at": "2024-06-10T14:00:00+00:00"
  }
] }

A autoria sempre aparece (author.name) — acervo anônimo não cria pertencimento, é regra de produto, não detalhe visual. term mostra quando a nota foi escrita: "2024/1" ao lado do resumo muda completamente o valor dela pra quem está lendo em 2027.

4Ver uma nota específica
GET /api/v1/notes/{note}
// mesmo formato de uma linha da listagem, com body_md completo
// 404 se o usuário não tiver direito de ver esta nota (o scope de
// visibilidade filtra ANTES do model binding — não existe 403 aqui,
// é como se a nota não existisse pra quem não pode vê-la)
Nota de prova nunca aparece aqui. O acervo compartilha conhecimento — resumos, dicas, listas — nunca desempenho. Não existe (e não deveria existir) nenhum jeito de este endpoint devolver nota de matrícula ou situação de aprovação junto de uma anotação.
